RivalLens D2C — UI/UX Design System

Design the product around one promise: a D2C operator should understand where they are winning, where competitors are stronger, and what to test next without learning a complicated intelligence platform.

Primary users: founders + growth teamsPrimary UX: report-firstVisual tone: credible, premium, analyticalAvoid: dashboard overload

1. Design Principles

Action before analytics

Lead with the decision the user can make. Supporting evidence remains one click away.

Progressive disclosure

Show a concise competitive summary first; reveal raw evidence, timelines, and source detail on demand.

Relative, not absolute

Every important competitor metric is framed against the user's brand or the competitor's own baseline.

Trust through provenance

Strategic claims include evidence count, confidence, and source links so the user can verify them.

D2C vocabulary

Use offers, bundles, UGC, PDP, subscription, shipping threshold, creative angle, and AOV—not generic BI language.

Decision compression

The interface should reduce dozens of inputs into a small number of meaningful tests, not expose every collected datapoint by default.

5. Visual System

Palette

Neutral white/gray base, near-black text, one confident indigo primary. Semantic green/amber/red only for meaning.

Typography

Inter or Geist. Strong 28–36px page titles, 20–24px section titles, 14–16px body, 12–13px metadata.

Density

Medium density. More like Linear/Stripe operations UI than a marketing landing page.

Cards

Use only when the content is a coherent object. Comparisons and evidence belong in tables/lists.

Icons

Single icon family, restrained use. Icons support recognition; they do not replace labels.

Motion

150–220ms transitions, subtle reveal of evidence drawers and refreshed results; no ornamental animation.

6. Interaction Model

  • Click a claim → evidence drawer. Users see the source, timestamp, before/after values, and why the signal exists.
  • Click a competitor → contextual detail. Preserve the current lens and comparison context when possible.
  • Filter by lens. Storefront, Ads, Instagram, X, Product, Offers, Positioning.
  • Save a recommendation as a test. Future-ready action for task integrations without adding full project management to V1.
  • Refresh is asynchronous. Show current data immediately and a clear “refreshing” state rather than blocking the screen.

7. Marketing UX

Activation moment

The first “aha” should happen when RivalLens identifies one clear advantage and one meaningful competitor gap from website data alone.

Value framing

Use “what to test next,” not “AI insights.” Sell reduced research time and better competitive decisions.

Retention loop

Weekly value comes from new material changes, creative patterns, and updated opportunity ranking—not a static dashboard.

Trust copy

Use “observed,” “appears,” and “evidence suggests” for competitor conclusions. Avoid pretending to know private ROAS or causal outcomes.

8. Responsive & Accessibility

  • Desktop is the primary intelligence workspace; tablet remains fully functional; mobile prioritizes report reading and evidence review.
  • On mobile, comparison tables become horizontally scrollable with the user's brand as a sticky first column.
  • Every drawer/dialog has a visible or screen-reader title; keyboard navigation must cover tabs, filters, tables, and command search.
  • Color cannot be the only signal for advantage/risk; pair with text/icon labels.
  • Loading states use skeletons; errors explain which source failed without hiding available analysis from other sources.
