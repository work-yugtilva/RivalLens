RivalLens D2C — Implementation Plan

Build the smallest vertical slice that can prove RivalLens creates useful competitive decisions. Website intelligence ships first; social and Meta complexity are added only after the evidence → signal → report pipeline is working.

Method: vertical slicesAI-assisted developmentRelease gates: tests + evidence qualityAvoid: connector-first overbuilding

1. Delivery Strategy

Vertical slices

Each phase ends with a user-visible capability running through UI → API → DB → jobs → evidence → report.

Contract-first connectors

Define schemas/interfaces before platform-specific code so providers remain replaceable.

Fixtures before scale

Build a corpus of representative D2C pages/posts/ads and lock expected extraction behavior.

AI last in the pipeline

Use deterministic extraction and metrics first. Add AI interpretation only after structured data is trustworthy.

2. Phase 0 — Foundation

Goal Establish the repo and contracts so agents cannot accidentally create three competing architectures.

  • Create pnpm monorepo with apps/web, packages/db, domain, schemas, intelligence, ai, connectors.
  • Initialize Next.js, Tailwind, shadcn/ui, Supabase client/server setup, Drizzle, test framework.
  • Create environment validation and secrets policy.
  • Implement organizations, memberships, brands, competitors schema + RLS tests.
  • Define shared connector, snapshot, observation, signal, and report Zod schemas.
  • Set CI: install → typecheck → lint → unit → database tests.
Exit gate: a signed-in user can create a brand and competitor and cannot access another organization's data.

3. Phase 1 — Website Intelligence MVP

Goal Prove the core product without social APIs.

  1. Brand URL onboarding and source discovery.
  2. Website connector: HTTP-first, Playwright fallback.
  3. Snapshot storage + content hashing.
  4. Commerce extraction: products, prices, discounts, bundles, shipping, guarantees, subscriptions.
  5. Positioning extraction: headline, value proposition, audience, proof, primary CTA.
  6. Observation storage and before/after diffing.
  7. Comparison engine: user brand vs 3–5 competitors.
  8. First four-part report: advantages / rival advantages / working patterns / what to test.
  9. Evidence drawer UI.
Critical validation: manually review at least 20 D2C sites across multiple storefront implementations. If extraction quality is poor, do not proceed to social.

4. Phase 2 — Social Intelligence

Goal Add content-performance evidence without breaking report simplicity.

  • Implement X connector behind shared adapter.
  • Implement Instagram professional-account connector behind shared adapter.
  • Store social posts and metric snapshots.
  • Calculate relative performance against each account's own historical baseline.
  • Classify hook, topic, format, CTA, promotional intensity, founder-led/UGC/product style.
  • Cluster comments/replies into recurring customer themes.
  • Add Social lenses to Rival and Compare screens.
  • Allow cross-source signals only after sufficient data coverage.

5. Phase 3 — Meta Ads

Goal Add paid-creative intelligence without making Meta access a single point of failure.

  • Create provider-neutral ad schema first.
  • Implement manual Ad Library / creative import path.
  • Add one compliant provider connector if commercially justified.
  • Classify creative format, hook, angle, offer, CTA, landing page, UGC/demo/testimonial style.
  • Track first/last observed dates and repeated creative families.
  • Add ad-specific comparison and opportunity rules.
  • Explicitly prohibit unsupported spend, ROAS, conversion, and targeting claims.

6. Phase 4 — Cross-Source Intelligence

  • Evidence graph and weighted signal_evidence relations.
  • Confidence rules based on source diversity, recency, extraction confidence, and repeated observations.
  • Opportunity ranking using impact × confidence × effort heuristics.
  • Report revision history and material-change detection.
  • Weekly monitoring summary / in-app notification layer.
  • Cost-aware job scheduling and organization-level budgets.

10. MVP Release Criteria

  • User can create a brand and monitor at least three competitors.
  • Website analysis extracts a useful baseline on the majority of the test corpus.
  • Report contains evidence-backed comparisons and no unsupported private-performance claims.
  • One failed source does not prevent report generation.
  • RLS tests prove tenant isolation.
  • Background tasks are idempotent and retry safely.
  • Core workflow works on desktop and mobile.
  • Production telemetry shows connector status, job failures, AI cost, crawl cost, and report generation latency.

11. Post-MVP Order

  1. Shopify first-party integration.
  2. Meta Ads Manager integration for the user's own brand.
  3. GA4/Klaviyo first-party performance context.
  4. Saved experiments and outcome tracking.
  5. Category-specific D2C models (beauty, apparel, supplements, etc.).
  6. Only after D2C proves value: separate RivalLens B2B/SaaS product model.
Do not prematurely generalize. A generic competitor intelligence platform will weaken the strongest part of the current thesis: D2C-specific offers, creative, storefront, and social intelligence.
